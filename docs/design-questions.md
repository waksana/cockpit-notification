# 后续体验与平台问题

Current 0.1.18 implementation choices are in the [implementation guide](implementation.md); published assets belong to their corresponding Release.
阅读采用同一 block 任意部分连续可见 600ms；内存账本、按身份核销和延迟推送设计保持不变。
本页保留不能由合成用例代替的边界及尚未确认的优化，不将候选方案当成已实现能力。

## 原生分类

用户 2026-09-24 确认所有模型用同一规则：主 Agent、非 ephemeral、正文非空且没有工具请求即本轮回复，
不看 phase。此前只认 `final_answer`，导致不提供 phase 的模型（如 Claude）完全不产生回复未读和推送。
后续升级 SDK 要重跑独立、隔离的契约用例，确认无工具请求仍表示交还控制权。
ask 采用宿主当前 requestId，已结束请求撤销提醒，不伪造一个可回答的旧原生请求。

## 阅读与布局

同一 block 任意部分实际连续可见 600ms 是呈现策略，不是眼动或理解判断；滚动不要求固定句子停留。
真实手机、辅助技术、超长 markdown、缩放和复合滚动容器仍应持续回归。
未读底色必须画在实际正文内，不通过挤压 chat 内容或关闭宿主性能优化来“修好”裁剪。
明暗主题、减少动态效果设置及 `content-visibility: auto` 下的显示均应回归。
连续曝光不足 600ms、曝光中断或核销请求尚未到达时，仍可能收到通知；如要进一步抑制提醒，
应另讨论策略，不把“正在读”和“已经读过”偷偷合并。

## 推送和手机

需要目标设备的真实安装和授权才能确认平台送达行为；本轮不替用户订阅或发送真实实验通知。
Safari/iOS tag、推送可见性要求、多个安装身份、睡眠后的角标清理、浏览器剔除 worker 等
不能由 Chrome 合成执行结果代表。

当前没有每次已读的清除 push。休眠设备上的旧通知和数字可以保留到下次获准执行，
通知中心条目数不保证等于 U。已经入平台管道的提醒可能迟到，不承诺无闪现或 exactly-once。
通知点开只进入对应聊天，不承诺任意旧消息秒定位。

## 更快推送与前台免打扰（候选，未确认、未实现）

当前方案已经把网页即时未读与系统推送宽限分开。若要让“无人看的会话立即推送，
有人正在看的会话暂不推送”，可另加模块自有的短期前台关注信息，只用于选择推送策略，
不用于已读核销：没有有效关注时立即推送；有关注时留一个有界窗口等待真正的 READ。

这需要明确关注的范围、失效时间、掉线/切换竞态和多设备行为；单凭在线连接或选中 session
不能证明新消息实际可见。关注信息过期或阅读确认未到时仍需恢复提醒，不能永久吞掉未读通知。
它比固定短暂宽限多了一套需要维护的瞬时信息，因此不是当前版本已采用的简化。

在后端尚未收到具体阅读确认时，“零等待发送”与“保证正在看的消息永不产生系统通知”
不能同时保证。按前台关注抑制提醒只是另一种免打扰策略，必须与“已读”区分；
不能为消除提醒而提前清空未读集合，也不依赖所有平台都允许 worker 静默吞掉 push。

## 工程边界

未读账本重启清零，不补停机历史；长期运行需要留意已核销身份增长及明确的容量错误。
本次配套宿主为[安装指南](installation.md)中的精确源码 SHA，不能安装到不支持 shared-surfaces v1 的旧包。
版本发行遵循固定源码和原始 CI artifact；生产安装和退出/重启仍需另外授权。
