# 实现前仍需细化的问题

**尚未实现。** 已经决定的内存账本、批量核销、完整快照、延迟推送和设备清理不再重复选型，
其精确规则以[状态机](state-machines.md)为准。本文只维护剩余问题。

## 1. 原生最终回复与 ask 适配

固定 SDK 1.0.13 的公开事件没有跨所有模型都可靠的 final-only 布尔字段：
`assistant.message` 可以包含中途说明，phase 可选，turn end 是模型循环的一次结束；
某些实际处理结束边界是临时事件。不能按关键词或空 toolRequests 推断全部最终回复。

实现前要确定主 Agent 归属、显式 phase、无 phase 情况、分片归并、取消/失败与排队接续的
判定规则，以及不能确定时的明确边界。模块不做历史补算，并不等于可以误把实时进度计入。

ask 的 requestId、toolCallId 与历史身份需要统一映射；提问区和消息行不能计算两次，
下一题与原请求更新要区分。前后端必须能在最终入账前使用同一个 MessageKey 上报阅读。

原生事件来源也必须证明是当前运行代的新事件：普通回放、resume 后旧事件、UI 历史加载
不得重新加入未读。不能通过自己拼装 opaque cursor 或扫描 native home 来解决。

## 2. PRESENTED 的确定条件

已确认只有具体呈现才能产生 READ，打开聊天不清空。待确定：

- 短消息的稳定可见时长，快速掠过与程序滚动的处理。
- 长回复阅读结束条件，不要求整条同时在屏幕内。
- 折叠内容、窗口缩放、辅助技术和键盘浏览。
- ask 当前区域/历史区域的共同身份及呈现确认。
- 已在本客户端呈现但当时尚未建立有效 generation 的重新确认。

不新增用户视线检测，不每次滚动扫描全量消息。宿主只提供通用呈现事实和挂载能力，
模块执行阅读策略，双方接口还需确定。

## 3. 容量、参数与条目失效

状态机以参数表达推送等待 D、阅读批量窗口 B；具体默认值和允许范围待确定。
同样需要落定批量 keys 上限、完整快照上限、M/A 容量、通知任务并发与超限错误。

不能静默截断快照或逐出核销凭据。若没有可证明的重放截止边界，A 在整个 generation 保留，
必须如实评估它的增长，而不是只以“未读很少”推断总内存固定。

原生 session 确认删除、rewind 移除消息、ask 已解决但未读时是否以及如何撤销条目，
仍待讨论。不能把无权限、暂时 unloaded 或历史读取失败当作消息被删除，
也不能偷偷将“已回答”改成“已读”。

## 4. 宿主通用接线

待设计而非当前已有：

- 稳定消息/ask 身份、可见性与外侧红线挂载。
- 会话数字和全站汇总、模块权限设置入口。
- 模块插入完成后的通用 SSE 状态变化提示；不新增专用未读连接或每次 READ 广播。
- 稳定 Service Worker 作用域、资源 URL、模块版本与停用清理。
- 页面/worker 的角标和通知串行执行、少量版本元数据共享，以及外部认证适配。

当前全局 session SSE 不携带所有会话的每条最终回复 ID，不能当成完整未读同步流。
同源反向代理、HTTPS、Service Worker scope 和后台请求认证必须在实际支持环境中核对，
不能因“用户已登录页面”就假定后台一定能重新取快照。

“首条未读”导航如需提供，仍只考虑复用原有分页和唯一滚动所有者的可取消定位；
不为通知模块重做双向历史窗口。是否首版包含该入口仍待确认。

## 5. 推送配置与平台

已确定不为 READ 发送清除 push；新消息提醒是模块后端主动发送的独立路径。
需要进一步选定：

- 固定版本的发送依赖、推送服务错误分类与超时；最小状态机不自动重试 UNKNOWN。
- 密钥与订阅的稳定保存、订阅撤销/更新、多设备及多个 PWA 安装身份。
- 消息内容的最小展示策略，默认是否只显示“有新回复/需要回答”与会话入口。
- 浏览器支持、通知 data/枚举/关闭、tag 限制及迟到 push 的合规处理。
- generation 不同的后台 push 如何取得权威实例绑定；无法认证/离线时如何说明滞后。

推送服务受理、设备显示和用户阅读必须分开。旧 push 不能让 U 复活，
但不能假定所有平台都允许静默丢弃可见 push；也不承诺休眠设备即时清理通知。
VAPID、subscription endpoint/keys 和设备标识不是公开配置，不进入源码、日志或 bootstrap。

## 6. 工程与交付

未读存储语义已经是内存 Map/Set 等等价结构，不再设计持久未读数据库或停机补读。
具体运行包、锁定依赖、宿主 SDK pin、CI/Release 与仓库门禁仍未实施。
可以参考 cockpit-file 的交付流程，不复制另一工作树依赖或不适用的业务假设。
