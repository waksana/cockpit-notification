# 首版实现与运行边界

本页记录 0.1.15 当前源码功能；GitHub Release 资产与具体实例的安装状态另行核对。
要求通用 module/event、menus v1 与独立 shared-surfaces v1；精确宿主支持见[安装指南](installation.md)，
历史发行版的 UI v1 本身不证明新增 badge 样式存在。
源码/包身份以 `tooling/host-sdk.json`、模块 manifest 和包内 `module-build.json` 为准。

## 已落定的实现选择

| 项目 | 首版选择 |
| --- | --- |
| 运行时 | Node 24.20.0、TypeScript、宿主可信主进程模块 |
| 未读账本 | 内存，模块重新激活新 generation；不补历史 |
| 计数 | 每 session 的不同未读 MessageKey 数量，全站求和 |
| 核销 | 批量具体身份，先整批校验再原子处理；保留本代核销凭据 |
| ask 身份 | 宿主当前 AskRequest.requestId，与控制投影和提问区共享；不是伪造原生 requestId |
| 失效条目 | 已回答/取消/替换的 ask 撤销提醒；确认删除会话或 rewind 撤销受影响会话提醒 |
| 阅读 | 同一消息 block 任意部分前台实际连续可见 600ms；滚动不重置，完全不可见/失焦/后台重计 |
| 最终回复 | 只接收主 Agent 明确 `final_answer` 的消息，直接入账 |
| 推送 | 模块后端调用标准 Web Push；等待窗口默认 3000ms，已核销的不再发送 |
| 设备配置 | VAPID 和推送订阅与未读账本分开保存，私有模块数据目录 |
| UI | Web API v2 state 注册、message/sessionStatus middleware、独立 menus v1 注册；菜单只开关本设备通知 |
| worker | 模块专属稳定 URL，narrow scope，不控制 Chat、不开离线缓存 |

Web state 服务复用既有未读和设备逻辑，HTTP、版本与批量核销仍由模块管理。
组件增强只观察、展示并调用 state actions，不新增 HTML 包装或空占位容器。
消息完整性仍来自宿主真实呈现事实，组件组合不能把流式片段提前当成已读。
展示接入不另建账本；本次增量同步的核销回执和模块/worker 同步消息见下文接口说明。

## 时效与等待窗口

未读同步和系统提醒是两条路径，不能把它们合称为“消息延迟几秒”：

| 环节 | 当前行为 | 目的与影响 |
| --- | --- | --- |
| 确认新未读 | 符合原生分类条件后立即入账并发布 SSE | 不等待 Web Push；连接正常时网页未读高亮、会话数字直接消费增量，总数保留为内部派生状态 |
| 阅读判定 | 已完成消息 block 任意部分实际连续可见 600ms | 排除流式片段、少于 600ms 的经过和后台页面；坐标/可见内容变化不重置 |
| 已读请求合并 | 150ms 合并窗口，每批最多 128 个身份 | 减少 HTTP 请求；后端核销后立即发布删除增量，网页不等推送计时 |
| 系统通知投递 | 新未读入账后默认等待 3000ms | 给阅读确认到达后端留出窗口；开始发送前仍检查未读，已经核销则取消尚未发送的任务 |
| 同步检查点恢复 | HTTP 回执/push 的版本未被 SSE 覆盖时，最多等 3000ms 再补一次 GET | 只用于恢复缺失增量，不是每条 SSE 的延时，也不是每次已读固定 GET |

正在看的消息 block 通常能在推送窗口内核销，因此可能短暂出现未读标记，
随后随删除增量消失，且不发出尚未开始的系统推送。但页面前台、选中了该 session
并不等于看到了新消息；该 block 完全在视口外、曝光中断或请求受阻时，仍可能收到通知。
两个阅读/合并窗口及网络往返都不能简单当成严格的端到端耗时保证。

观察只使用公共 bodyRef 和消息身份。每帧把消息矩形与 visual viewport、实际祖先的
横/纵裁剪区域相交，再在剩余区域取点命中正文或其子元素，排除完全遮挡；
hidden/inert、CSS 隐藏、页面 visibility/focus 和当前 session 资格仍是门槛。
不再区分长短消息或末尾，不比较矩形签名。持续滚动只要同一 block 保持部分可见就连续计时，
不要求固定句子停留。完全离开再进入从零开始；会话、身份、资格变化与卸载取消旧观察。
失焦、前后台和会话切换即使发生在两帧之间也会打断计时。每条消息独立确认，不扩展为会话全读。

网页活跃且平台支持时，PWA 角标可随同步后的集合更新，不必等 Web Push。
页面休眠时，桌面/PWA 图标可能依赖 push 才更新，因此会包含推送窗口及平台调度延迟；
这与网页未读高亮/会话数字的更新路径不同。
将 `pushDelayMs` 设为 0 只会取消推送宽限，不会让后端提前知道稍后才到的阅读确认，
也不能保证正在看的会话不产生系统通知。候选优化见[后续体验与平台问题](design-questions.md#foreground-suppression)。

## 明确 final 直接入账

0.1.13 按用户确认只订阅宿主实时 `onNativeEvent` 中的 `assistant.message`：
主 Agent、非 ephemeral、`data.phase === 'final_answer'`、正文非空、无工具请求且消息身份有效，
就立即加入未读集合并发布该条 delta。不要求收到 start/delta/turn end/idle，也不按内容关键词猜测。
同一回合多条明确 final 分别入账；之后的取消、错误或工具事件不撤销已经发布的正式回复。
READ、ask 退役、确认删除与 rewind 仍各自按账本规则处理，停止整个模块仍会释放内存。

SDK 1.0.13 的 phase 是可选字符串。无 phase、commentary 或未知 phase 一律不计，
即使后来正常 idle 也不补猜；使用不提供明确 final 标记的模型可能漏计，这是已接受的边界。
提供方 `apiCallId`、chunk 编号和 turn 关联信息不参与判断，也不缓存其摘要。
未读去重直接使用既有 `(sessionId, kind, messageId)` 账本身份，不另建原生事件去重副本。

“新”来自宿主公开的实时观察通路，不来自 phase 本身。历史分页与 bootstrap 快照不接入该处理器，
不加载或扫描历史、不补启用前消息。模块不再用流式片段证明新旧；如果把历史事件人为送进实时处理器，
仅凭同样的 JSON 形状无法区分它与新事件。重复实时投递和已读先到仍由本代身份保证不复活。

### 回复证据生命周期与旧错误

旧版的 15 分钟检查先于 idle/abort 清理，后续事件可能先丢弃证据并抛出
`CLASSIFIER_WINDOW_EXPIRED`。0.1.11 取消时间限制；0.1.13 删除整个有状态分类器，
包括候选、流式身份、final 暂存、turn 容量和事件去重集合，不再有任何回复证据窗口。
纯事件过滤不保留跨调用状态；正文非空检查耗时随当前输入长度增长，预览只读取前 4096 个
UTF-16 码元并最多保留 120 字符，不缓存完整正文、不累计 token。
真正需要保留的只有既有未读/核销身份及待发推送，仍受账本容量和发送限制约束。
不满足 final 条件的事件忽略；符合 final 条件但身份非法时报告 `INVALID_REPLY_IDENTITY`，
账本、发布和推送错误仍明确报告，不以删除错误处理来消除提示。

旧宿主 `context.report` 按模块保留最后一个错误，后续成功不会删除它；新页面/PWA 初始化读取
`/_modules.errors` 后会再次显示。重复打开看到提示不证明又发生了新超时。模块没有公共接口
清除此记录，也不能用一次成功掩盖其他故障；宿主错误历史/关闭/一次性浮层另见
[waksana/cockpit#67](https://github.com/waksana/cockpit/issues/67)，本版不修改宿主或部署生产。
旧版已丢弃的临时证据无法从模块内存恢复，不补算过去漏记的未读/推送；
已确认的读/未读身份不因本次分类清理变化。未来经授权冷加载仍遵守既有重启新代、不补历史的边界。

## 网页入口与会话行

`menus` 声明一个全局“开启通知 / 关闭通知”动作，不再使用 `globalNavigation` middleware。
状态直接来自 DeviceBridge 的快照与订阅，动作仍由该服务执行；宿主拥有原生条目、分隔、排序和交互生命周期。
没有菜单外的铃铛、全局数字或通知设置 dialog，也不增强管理页标题栏。
设备操作进行中禁用重复点击；不支持推送时禁用开启，已有浏览器订阅仍允许关闭。
仅浏览器创建订阅、后端登记失败不算开启成功；受支持环境继续显示“开启通知”，
用户重试会复用已有浏览器订阅，不重复请求权限或自动注销它。
错误走宿主通用反馈，不伪装为开关成功；重新加载页面或重连可恢复未读同步。
PWA 角标仍使用内部总数，关闭本设备推送不改变未读集合。

会话徽标作为 sessionStatus 的末尾 children，位于原生状态文字右侧。
徽标使用随字体缩放的 1.5em 等高最小宽度（默认 12px 元信息字体下为 18px）、
border-box 和居中 inline-flex；单个数字呈圆形，
多位数字自然横向扩展，保留不收缩、无点击行为和原生未读可访问说明。
配套宿主在待决策时显示“待回答”，不同时显示“回复中”和“选”；正常运行仍为“回复中”，
错误状态仍明确显示“出错”。这些原生状态文字由宿主负责，不由通知模块猜测。

### 未读计数的组合几何验收

`ck-badge` 是通用文字标签基础，不承诺圆形计数；模块保留自己的计数几何变体，
复用公共字体和颜色。遵循 [Ant Design Badge](https://ant.design/components/badge/) 对
数字计数与无数字圆点的区分：多位数自然扩成胶囊，不强行塞入小圆，不新增计数截断策略。
原生状态在前、非交互计数在后，不能以复用 class 为由移除防压缩和单行约束。

在已构建的配套宿主 CSS 上运行轻量预览，不启动宿主、不读取会话或推送配置：

```sh
node scripts/badge-preview.mjs /absolute/host/apps/web/dist
```

打开输出的 loopback URL。页面仅使用合成行，加载真实宿主和当前模块 CSS；
当前 Sidebar 行结构作为集成样本（宿主结构变化时同步样本），不是模块生产代码的私有选择器依赖。
它不代替编译后 middleware 的非交互、计数和状态测试。
预览对 1/8/9/10/99/128/1000、220px/360px 容器和双倍徽标字体自动测量，
包含待回答、回复中、出错、空闲以及 stale、卸载、选中行：
单位数字宽高相等、胶囊圆角、文本在徽标内、徽标未越过裁剪祖先、不收缩且不换行。
验收覆盖浅/深主题、手机正常缩放、桌面 200% CSS 缩放及 RTL；切换后调用
`window.measureBadges()`，页面末尾结果必须为 PASS。页面正常纵向滚动不视为行内裁剪。
320px 手机视口再叠加 200% CSS 缩放会让样本可用行宽不足 128px，
宿主固定头像和状态列无法容纳而发生裁剪；本修复不改变宿主网格，
不宣称这种极窄组合通过，也不通过缩小数字或省略计数掩盖它。
不能仅凭最终截图、CSS 文本匹配或普通状态测试宣称几何正确。

## 回复未读底色

仅已完成且已知未读的主 Agent 回复使用浅色底色；通过公共 `MessageProps.className`
添加样式类，在实际消息正文内绘制暖黄色底色：35% 的 `--ck-color-accent` 与 65% 的
暖金色 `#f2c94c` 混合，再以 18% 不透明度叠加，不覆盖明暗主题原有背景与文字色。
保留原有 `className`、`style`、组合 bodyRef，以及 children/adornment 和可访问性属性。
向 Base 组合 `cn-message-highlight` / `cn-unread` 类，将原装饰线改为视觉隐藏的 `cn-unread-label`，
保留 `role="img"`、`aria-label="未读消息"` 语义；移除装饰线高度测量及其 ResizeObserver。
不增加可见装饰节点、DOM 包装、padding 或 margin，不改变正文宽高、换行、对齐与滚动几何。
底色圆角取宿主 `--ck-radius` 与 3px 的较小值，不裁剪正文或增加间距；圆角在淡出期间保持不变。
新增未读立即显示底色，权威未读状态移除后以 1000ms ease-out 先快后慢地淡出；
未读期间不自动消失，`prefers-reduced-motion` 下禁用过渡。

`content-visibility: auto` 的绘制包含会裁剪越界装饰；正文内底色避免这一问题。
本次只改变模块展示，不修改宿主、不关闭或绕过宿主性能优化；会话徽标、未读协议、
推送及阅读判定均保持不变。

## ask 与过期提醒

本模块观察宿主已经拥有的原生控制投影，而不是额外查询用户输入面板。
前端提问区与后端投影使用相同宿主 requestId，避免与 SDK toolCallId 混用。

ask 被呈现并核销时只清未读，不替用户回答。
问卷不添加未读高亮。message middleware 仍组合原组件的 bodyRef，
观察同一 block 任意部分前台实际连续可见 600ms，并将 requestId 交给共享 state 批量核销；
不增加 DOM 包装，不改选择项、请求草稿或回答操作。
ask 被回答、取消或替换时，尚未读的提醒撤销，避免留下无法再次打开的红点。
这称为“撤销过期提醒”，不是谎称用户读过。
rewind 后保守撤销该会话的当前模块提醒，不扫描原生历史猜测部分消息是否仍在；
普通 compaction 和 session unload 不等于删除。

## 接口和传输

账本接口使用模块专属、摘要绑定的 API 路径。`GET /state` 返回完整一致快照；
`POST /read` 接收 `{ generation, keys }`，旧 generation 明确拒绝。
订阅管理在同一模块 API 下，不写入本体全局配置。
订阅身份是规范化 `new URL(endpoint).href` 的 UTF-8 SHA-256 小写十六进制，
使本设备恢复时可只查询登记状态，不自动重新注册已经取消的订阅。

`POST /read` 的成功体改为 `{ generation, revision, acknowledged }`，不包含快照。
回执只确认请求并检查 SSE 同步进度，不修改网页未读集合，也不提供给 worker 作为已读证据。
新增、核销、撤销的实际账本变更经 `publish()` 发送 `module/event`，模块 payload 是
`unread/delta { generation, fromRevision, revision, added, removed }`。
每事务 R 加一、每次 GET 不加；重复事务不加。超出 64 KiB/增量数量预算发版本同步提示，不截断。
前端直接应用连续增量，切换 session 不 GET。初始化、重连、新代、断档或版本屏障未追上时才完整读取；
后台不轮询，保持连接期间可以应用 delta，回前台若状态完整不查询。
普通同 generation push 使用携带的总数，不为每条通知额外查询完整快照；
未知/新 generation 需要宿主 bootstrap 和完整状态查询来确认绑定。
Worker 向页面转发 push 的版本检查点，已由 SSE 覆盖则不再 GET；
网页只把接受快照/连续增量后的完整状态交给 worker。

未读上限 10,000 条、每代保留身份上限 100,000、核销批次上限 128；
达到上限明确报错，不通过静默丢弃身份让已读复活。发布前应评估长期运行的身份增长。
回复过滤无候选、turn 或原生事件身份缓存；不订阅 token 事件，不设回复时间窗口。
最多 64 个设备订阅，模块总发送并发为 4；请求超时 10 秒、push TTL 60 秒。
已开始发送的结果未知时不自动重试，核销只能取消尚未开始的任务。
取消设备订阅时，已为该设备分配但尚未开始发送的尝试进入终态；
即使随后以相同 endpoint 重新启用，也不恢复这些旧尝试。其他设备与后续新消息不受影响。
前端设备启用/停用会使先前的订阅查询失效，晚返回的查询不能覆盖已完成的操作。

私有 `push-config.json` 保存 VAPID 和设备订阅，不包含未读账本。
模块配置接受 `pushDelayMs`（0–60000，默认 3000）、`vapidSubject` 与 `extraPushHosts`，
拒绝未知字段。默认 subject 为本仓库 HTTPS 地址；额外推送主机最多 16 个明确公共 DNS 名称，
不能通过它启用私网、loopback 或任意 HTTP 端点。

默认推送端点允许 Google `fcm.googleapis.com`、Mozilla `updates.push.services.mozilla.com`、
Apple 的 `.push.apple.com` 子域，以及 Edge 使用的微软 WNS `.notify.windows.com` 子域。
WNS 子域可随分区变化，按完整 DNS 标签后缀匹配，不放宽到任意 `windows.com`；
微软的[通道 URI 校验说明](https://learn.microsoft.com/en-us/windows/apps/develop/notifications/push-notifications/wns-overview#requesting-a-notification-channel)
要求校验 `notify.windows.com` 域。仍拒绝明文 HTTP、显式端口、用户信息、片段和超长地址，
发送时继续拒绝私网/回环/保留 DNS 结果，不跟随重定向。
0.1.3 修复 0.1.2 遗漏微软域名导致 Edge 登记返回 400 的兼容问题；不关闭地址保护，
不记录或要求用户公开完整订阅 URL/密钥，也不把允许登记等同于真实设备已收到 push。

## 系统通知标题、预览与点击

通知标题为“新回复：会话标题”或“待回答：会话标题”。会话标题只取宿主已有的
snapshot/session-added/session-patch 控制事件，维护有界的内存展示缓存；发送时使用最新已观察标题，
删除会话或模块停止时释放。不另查原生历史；未观察到标题时明确使用“会话 + 短 ID”，不猜标题。
控制快照中的旧 ask 不因读取标题而重新登记未读。

回复摘要只从分类器确认的最终答复提取，问卷摘要取当前 ask 的 question。
最多读取文本前 4096 个 UTF-16 码元，清理常见 Markdown 标记、控制字符并合并空白，
保留最多 120 个 Unicode 字符，超长带省略号；会话标题最多 64 个字符。
不是模型生成的内容总结，也不保证各种设备恰好显示两行。没有可用文字时显示打开会话查看的提示。
不获取工具、思考、子 Agent 或历史全文来拼摘要。

账本、核销凭据、SSE delta 和快照继续只传身份/版本，不加入正文或标题字段。
短摘录只在分类证据与尚未完成的推送计划/发送中暂存，不由服务端写盘；
终态计划不继续保留摘要。Web Push payload 带标题和短摘录，实际通知内容由 OS 保存和展示，
可能在锁屏可见，不把“未读不落盘”描述成“设备上不会保留通知内容”。

Worker 原样使用 payload 的标题和正文，不追加 `from Cockpit`；浏览器/OS 自带的应用来源行
不属于可删除的正文。点击按原生 sessionId 打开对应会话：已有窗口的 URL 正好是目标会话时只聚焦，
多个匹配窗口优先选择已聚焦者；否则调用 `clients.openWindow()`，新开标签页还是复用 PWA 窗口由浏览器决定。
不发送 READ，不自动回答 ask，也不承诺定位到任意历史消息。

聊天页不在通知 worker 的窄 scope 内；`registration.active` 已激活不代表它控制聊天页。
`clients.matchAll({ includeUncontrolled: true })` 可以找到同源的非受控页面，但不授予导航控制权。
因此不调用 `WindowClient.navigate()` 重定向其他聊天窗口，不扩大 scope、不调用 `clients.claim()`，
也不增加页面消息导航协议。浏览器拒绝打开/聚焦时明确反馈，不自动重复打开或伪装成功。
0.1.4 修正了旧点击路径违反该控制边界的问题；重新授权或清除设备订阅不是这个问题的解决方式。

## 浏览器与手机的保证边界

网页数字和未读高亮来自完整快照及连续增量，通知与 OS 角标是独立的显示动作。
HTTP 成功可以早于未读高亮移除；页面需等对应 SSE 或恢复快照，随后底色按过渡设置淡出。
在线其他客户端同时消费已读增量。
通知点击只导航，不自动核销整个会话；系统划掉通知也不减少 U。

手机收到 push 时显示该条逻辑通知，并按可用能力更新总角标。
已读通知通过具体身份/覆盖版本清理，不能仅凭 U 为零把所有新旧通知全部删除。
同代迟到 push 不会倒退角标，但 worker 未保存完整已读集合，不能仅凭旧 revision 清理该通知；
它可以保留到下一次有效完整集合被应用，不为即时清理追加逐条 HTTP。
没有通知权限或平台不支持 badge 时，网页未读仍然工作。

需要 HTTPS/可信本地开发源，以及安装/权限允许的 PWA 环境。
没有对真实 Apple/Google/Mozilla 推送端点发实验通知，也没有 iPhone 真机认证；
合成 worker 和浏览器 fixture 的结果不能替代真实平台送达保证。
休眠设备的即时清理、推送必达、无重复系统展示及迟到提醒的无闪现均不作保证。

## 仍未包含

- 任意历史窗口跳转、源码/消息全文副本、停机补算。
- 持久增量重放、逐条 SSE ACK、后台轮询、清除用 push。
- 普通 plan/elicitation/系统错误作为新 U 类别。
- 模块管理平台、热加载、自动部署或重启。
