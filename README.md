# Cockpit Notification

Cockpit 的独立未读与通知模块：明确记录每一条未读消息，让消息旁的标记、会话数字、
PWA 角标及对应推送使用同一份状态。

**0.1.1 的增量同步已确认为正式功能，不再作为试用方案维护。** GitHub Release 当前仍为 0.1.0，安装资产以
[v0.1.0 Release](https://github.com/waksana/cockpit-notification/releases/tag/v0.1.0) 的资产为准，
不能把功能确认、发布资产和某个实例安装混为一谈。0.1.1 从固定源码构建安装，
需要配套宿主的通用模块事件通路，不能直接当作已发行宿主能力。
需要配套宿主的 Web API v2、
公共 UI v1 和窄作用域 worker；旧 Web 插口不保留兼容层。
包/宿主后端 API 仍为 v1；本次增量同步改变模块自己的核销回执和同步消息格式，需配套升级。
状态契约见[状态机](docs/state-machines.md)，实际能力与平台边界见[首版实现](docs/implementation.md)。

## 核心模型

**后端持有一份未读集合：监听符合条件的新消息加入集合，前端报告具体消息已读后由后端核销，
实际变更通过现有 SSE 发给网页。** 前端不另行判断哪些原生事件应计入未读，
也不靠 HTTP 已读回执直接修改显示；快照和连续增量是它的状态来源。

**未读入账、SSE 和网页红线/数字不等待推送窗口；延迟的是系统通知的 Web Push。**
批量发送已读和延迟推送只是这一模型上的请求合并与减少打扰，不是第二套未读状态。
所有权与边界见[产品要求](docs/requirements.md#核心模型与所有权)，
各类等待的区别见[时效与等待窗口](docs/implementation.md#时效与等待窗口)。

## 已确认的方向

- 统计主 Agent 的正式最终回复和 ask，不把思考、进度说明、工具执行和子 Agent 输出计入。
- 每条新消息显式记录未读；打开聊天不自动清空，看到对应消息后逐条转为已读。
- 未读回复左侧显示红线，画在现有内容外侧，不挤占宽度、不撑高、不改变与输入框的对齐。
  问卷/提问不画红线，但仍观察实际呈现并报告已读，不自动回答。
- 每个会话的状态行最右侧显示未读数量，支持的 PWA 图标显示各会话数量之和。
  网页不显示全局未读总数；汉堡菜单只提供本设备通知的开启/关闭，不另放铃铛或设置面板。
- 消息已读后消除对应红线、数字与通知；允许传输和操作系统造成延迟，不宣称跨设备瞬时一致。
- 模块持有自己的未读与通知数据；原生聊天、历史和消息身份仍以 Copilot 为准。
- 未读账本仅存内存，模块重启清零，不补历史；已读先到与重复事件由核销凭据处理。
- 网页只以完整快照和模块后端的连续 SSE delta 更新未读；HTTP 回执不改显示。
  切换会话不查询，只有初始化或失步恢复取快照，不让前端从原生聊天事件重新判断未读。
- 系统通知的 Web Push 延迟几秒，届时仍未读才发送；模块调用浏览器接口更新角标和清理对应通知，
  不另发“清除通知 push”，休眠设备允许延迟收敛。
- 系统通知标题使用“新回复：会话标题”或“待回答：会话标题”，正文显示内容短摘录；
  点击直接打开对应会话。系统自带的应用来源行由浏览器/操作系统管理，不重复拼进正文。

只有一个计数概念 **U：尚未确认已读的新消息条目数**，不再另设一套“通知未读数”。
完整规则及尚待讨论的问题见[文档索引](docs/README.md)。

## 命名与边界

仓库及计划中的模块标识采用 `cockpit-notification`，与 `cockpit-file`、
`cockpit-task`、`cockpit-assistant` 的单数模块命名保持一致。
这是项目命名约定，不表示行业要求通知系统只能使用单数。

本模块不是消息传输服务、原生历史副本或新的 Chat 实现。宿主只按实际需要补通用插口，
不把未读策略、推送订阅和业务记录放回本体。

## 实现与发行

源码提供内存未读集合、按身份幂等核销、完整快照及标准 Web Push 的模块实现，
通过注册共享 state 服务和消息/会话/实际导航菜单的组件 middleware 接入，不创建另一套 Chat，
不为 middleware 增加 HTML 包装或空占位容器。
构建基线和命令见[构建与安装](docs/installation.md)。推送密钥与设备订阅私有保存，
未读本身不落盘；真实平台投递仍受安装、授权、网络与 OS 行为限制。
发行来源与资产规则见[版本发行](docs/releases.md)，本次摘要见[发行说明](docs/release-notes.md)。
实现、发行、安装和服务重启分别授权，不因创建仓库自动执行。
